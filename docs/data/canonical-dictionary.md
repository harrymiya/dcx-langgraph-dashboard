# DB-02 canonical 字段数据字典

> **状态：目标设计，未实现。** 字段/键为评审基线，不代表数据库中已有列。所有示例为合成数据；不执行 DDL、不连接生产库。健康域写入关闭，须先确认健康数据责任 owner。

来源与边界：`jiankang_app_uniapp/docs/data-architecture-design.md` §§1–13、总体设计 §25；按 DB-01 保留 legacy 映射方式，并与 GOV-06 的租户/站点、Wish 与 Commerce 写主、预约/服务卡状态词汇一致。旧表仅映射，不自动回填、不双写。

## 通用字段约定

- **ID/FK**：主键为服务生成的不可变 UUID（可选 UUIDv7）。同站业务外键由 `tenant_id + site_id + entity_id` 组成，并声明 `ON DELETE RESTRICT ON UPDATE RESTRICT`。`plat_tenant` 和租户级 `crm_customer` 是显式目录/身份锚点例外；不允许跨 tenant/site 拼接。
- **租户/站点**：事实类实体均必填 `tenant_id, site_id`，在唯一键、外键、索引和服务端查询谓词中共同使用。`plat_tenant` 是根目录，`crm_customer` 是租户级身份锚点，不隐含站点授权；有效业务配置必须生成站点版本。
- **时间/有效期**：UTC `DATETIME(3)`；`occurred_at` 与 `created_at` 分开。生效期字段遵循半开区间 `[effective_from, effective_to)`；状态变更保留 actor、原因、请求 ID 和行版本。
- **敏感数据**：健康正文、直接身份与联系方式使用 KMS envelope encryption；可查找标识另存 HMAC 索引。不得以电话/union_id 为主键，不得将健康正文、token、Cookie、验证码、支付密钥写入日志或消息模板。
- **金额**：货币金额使用 `DECIMAL(18,2)` + `currency_code`（ISO 4217）；数量必须另带单位。余额缓存不是账本写主，金额纠错以反向分录表达。
- **删除/保留**：一般 FK 均 RESTRICT，无级联删除。主数据可按批准策略软删/匿名化；账本、审计和状态历史 append-only。具体保留期限由业务 owner/法规确认，本字典不虚构年限。
- **快照**：预约、工单、触达和报表固定引用发生时有效的服务/容量/资格/SOP/模板/consent/频控/口径版本；改规则建立新版本，不回写已有事实。

## 预约锁 bucket 唯一约束

`svc_resource_lock` 将预约时段拆成固定 5 分钟片段，每个资源 bucket 的唯一键是 `(tenant_id, site_id, resource_id, slot_start_utc)`。一次预约包含多个资源/片段时，先按 `resource_id, slot_start_utc` 排序，再在同一事务中一次性插入；任一 bucket 冲突则整个事务回滚。这里不采用“查询无冲突后再写入”的竞态方案。过期释放采用带 `lock_version` 的条件更新，状态变化先记入 history/outbox。

## 规则版本快照

预约保存所选 `service_version_id` 及资格/容量/计价规则版本；工单固定 `service_version_id` 与 `sop_version_id`；发送固定模板、consent、偏好/退订和频控决策版本；报表固定口径版本和 source watermark。模板/SOP/服务定义发布后不可原位修改。任何规则变更都产生新版本，已有预约、履约、触达和快照继续按其引用的旧版本解释。

## 术语状态映射

GOV-06 验收词汇“预约：待确认/已确认/已完成/已取消”对应内部 `PENDING/CONFIRMED/COMPLETED/CANCELLED`；内部也可保留 `HOLD/PENDING_PAYMENT/CHECKED_IN/IN_SERVICE/NO_SHOW/EXPIRED/RESCHEDULE_PENDING`。回访“待跟进/已完成”不在本次最小表组内展开。服务卡“有效/冻结/过期”对应 `ACTIVE/FROZEN/EXPIRED`，另有 `EXHAUSTED/REVOKED`；卡余额始终由 append-only 分录聚合。
